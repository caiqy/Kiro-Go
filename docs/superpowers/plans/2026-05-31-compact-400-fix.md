# Compact 请求 AmazonQ 400 修复 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 Claude Code compact 请求经 Kiro-Go 转发到 AmazonQ 时返回 400 的问题，通过自动声明工具定义满足 Kiro API 的约束。

**Architecture:** 在 `proxy/translator.go` 的 `ClaudeToKiro` 函数中，工具转换后检测 `kiroTools` 为空的情况，从 history 中收集工具名并自动生成最小化声明。同时增强 `trimLeadingAssistantHistory` 以跳过孤立的 tool_result-only user 消息。

**Tech Stack:** Go 1.x，标准库 `strings`，`go test`。

- **Modify** `proxy/translator.go` — 新增 `collectHistoryTools` 函数；修改 `ClaudeToKiro` 添加 auto-declare 调用；增强 `trimLeadingAssistantHistory`。
- **Modify** `proxy/translator_test.go` — 新增 6 个测试函数覆盖修复场景。

  - 生成 `KiroToolWrapper`（最小 schema: `{"type":"object","properties":{}}`）
  - 仅在名称实际变化时填充 `nameMap`
  - 返回 `([]KiroToolWrapper, map[string]string)`

- [x] 在 `ClaudeToKiro` 中添加 auto-declare 调用
  ```go
  kiroTools, toolNameMap := convertClaudeTools(req.Tools)
  if len(kiroTools) == 0 {

  ```

## 回归检查清单

后续修改 `proxy/translator.go` 时，需确认以下场景不被破坏：

1. **Compact 请求**：`tools:[]` + 长历史（含工具回合）→ 应返回 200，输出为 anchored summary
2. **正常 agentic 对话**：`tools` 非空 → `collectHistoryTools` 不被调用，行为不变
3. **纯文本对话**：无工具历史 → 不注入工具
4. **对话以 assistant 开头**：leading assistant + orphaned tool_result 被正确 trim
5. **对话以 user(text+tool_result) 开头**：不被误 trim
6. **工具名 sanitize**：含下划线/超长的工具名正确转换为 camelCase 并截断

运行命令：
```bash
go test ./proxy -run "TestTrimLeading|TestCollectHistory" -count=1 -v
```
